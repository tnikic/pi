# Tool-based completion contract for subagents

Subagents signal completion by calling a mandatory `report_done` tool rather than relying on the model's native stop reason, sentinel strings, or other heuristics. We chose this because tool calls are the most reliable signal in the pi event stream — models are trained to use tools and the parent already processes `tool_use` events. Native `stopReason: "end"` is fragile (models sometimes stop without emitting a clear reason, or produce a final text block that looks like completion but isn't), sentinel strings are prone to hallucination and regex fragility, and turn-count heuristics can't distinguish "done" from "still working." The contract is enforced structurally: the subagent's system prompt forbids bare text as a final message — `report_done` is the only valid completion path.
